# 《下一班火车》

你是初级工程师。发车前，你想把一行改动送上版本火车。去问负责人并不会通过，签字名单会从 1 个人长到 3 个人，再长到跨团队，再长到 VP 会议。

这是独立的小演示，不替换旁边的「准点发车」。

## 怎么玩

先选一个很小的改动：按钮改色、错别字，或注释里的句号。

每一关是一班车。手牌要花精力和人情，并且过一天：

| 牌 | 作用 |
| --- | --- |
| 去问问 | 不通过。审批树变长。 |
| 拉通对齐 | 有人说「原则上不反对」，名单再加一个人。 |
| 向上管理 / CC大老板 | 抄送之后有人点头。抄到 VP 那一步，可能请你去管流程。 |
| 偷换概念 | 把标题改成「体验优化」。合规和安全对峙时，特批才走得动。 |
| Hotfix特批跳过 | 剩下的签字全部跳过。 |
| 周末午夜突击 | 自己补完一个卡点的材料。 |

会碰到三个不主动出手、也不签字的人：流程卡夫卡·合规总监、薛定谔的负责人·安全专家、影子架构师。

四关签字更多、时间更短：修错别字、版本大联调、红线行动、封网期大促。

第 1 关只在「文案负责人」名下时，打出「周末午夜突击」就能进第 2 关。三条结局都能走到：

- 荒诞胜利：一行合并了，业务其实已经砍了这个按钮，当天上线当天被撤。
- 黑化结局：你坐到流程负责人的位子上，给下一班再加一道卡点。
- 虚无结局：合规报告 100 分，几个月没有东西上车，竞品先上了。

精力归零会辞职。天数归零，这班不要你，审批清零。安全要日志、合规不让记，还硬要合入，就是合规死锁。

## 本地运行

在仓库根目录：

```bash
npm test
npm start
```

浏览器打开 http://127.0.0.1:3000/next-train/

`npm test` 会先跑原来的发车游戏，再检查这一款：第 1 关能进第 2 关，三种结局和三种失败都到得了。

单文件页面：

```bash
npm run build:next
```

生成 `next-train/play.html`，给不能加载相对路径脚本的预览站用。
